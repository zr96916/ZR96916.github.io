## 三、核心规则口径

### 1. 工单状态机（三态闭环 · 最终口径）

```
待整改 ──子用户·开始整改──> 整改中 ──子用户·提交处置──> 已整改
  ↑                                                    │
  └────────── 主用户·验收不通过（已整改退为待整改）──────┘
                     主用户·验收通过 → 已整改（终态·归档同步台账）
```

| 状态 | 语义 | 进入方式 | 色标 |
|---|---|---|---|
| 待整改 | 主用户复核有问题，交办工单 | 终核判定违规生成；或验收不通过退回 | 红 |
| 整改中 | 子用户点击「开始整改」 | 子用户操作 | 金 |
| 已整改 | 子用户提交处置结果 | 子用户操作；验收通过后维持为终态 | 绿 |

**要点**：
- 「待审批」状态已删除。子用户提交即「已整改」，随后进入主用户抽样验收队列。
- 主用户验收通过 → 工单维持「已整改」（终态，归档并同步汇总台账）。
- 主用户验收不通过 → 工单由「已整改」退回「待整改」，子用户重新整改（不建新单，一单一案一号到底）。
- 状态键映射：PENDING=待整改 / IN_PROGRESS=整改中 / RECTIFIED=已整改。

### 2. 判定违规问题类别（四类，全原型统一）

| 类别 | 说明 |
|---|---|
| 案件来源不符 | 数据来源与线索归集要求不一致 |
| 案件类别不符 | 实案类别与模型应用类别不一致 |
| 案件模型关联不符 | 案件与监督模型的关联关系不成立 |
| 其他不符合 | 其他不符合应用规范的情形 |

统一覆盖：终核违规模态选项、子用户工单问题类型（含筛选下拉）、整改验收队列、汇总台账、驾驶舱异常分布环图。

### 3. 批次号规则

- 格式：`环节码-日期-当日流水`，如 `REV-20260615-004`（复核）、`CHK-20260929-004`（初核）。
- 环节码区分 REV/CHK/ARC 跨环节不撞；日期 8 位可口头对号；流水 3 位区分同日多批。
- 唯一性：全号建唯一索引，事务内「当日最大流水 +1」。
- 界面展示人类语义别名「第 N 批」，台账/工单流转用机器号。

### 4. 整改验收（抽样模式）

1. 输入验收比例（1–100，非法值拦截）；
2. 选择验收上限（10 / 50 / 100 / 200 件，默认 50）；
3. 点击「生成验收清单」：从**已整改工单池**（30 件）随机抽样，应抽 = 池 × 比例向上取整，超上限按上限执行；
4. 队列逐条验收：「验收通过」（维持已整改·归档）/「验收不通过·退回」（退为待整改），确认后**自动移出队列**并选中下一条。

### 5. 终核判定交互

- 判定违规：模态内**必选四类问题类别之一** + 交办去向 + 意见；确认后回写文书「最终评定」。
- 合规通过：确认模态，直接归档。

## 六、防呆与交互约束

- 开始整改：仅「待整改」状态可触发；
- 提交处置：整改说明必填且 ≥10 字；
- 验收比例：1–100 之外拦截提示；
- 验收上限：应抽超过上限时按上限执行，toast 明示；
- 验收队列：未生成清单时点验收按钮拦截；确认验收后自动移出并报剩余数；
- 登录：账号/密码非空校验，回车可提交。
