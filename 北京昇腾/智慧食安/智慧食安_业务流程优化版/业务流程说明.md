# 智慧食安 · 业务闭环优化版 — 说明

> 本目录是对原「智慧食安」静态原型的整体业务重构，重点不是视觉美化，而是把**风险发现 → 监管复核派单 → 商户整改/申诉 → 镇级审核 → 区级督办 → 主体档案沉淀**走成一条可追溯、可重复演示的跨端闭环。

## 与旧版的关系

- 旧版（父目录 `index.html`、`智慧食安_商户小程序.html`、`智慧食安_管理PC.html`）保留不动，作为对照基线。
- 优化版共用同一份数据源 `assets/mock-data.js` 与业务动作 `assets/business-flow.js`，两端写入同一 `localStorage` 键 `smartFoodSafetyDBV2`，因此**管理端的操作会同步反映到商户端**，反之亦然。

## 统一业务对象与状态口径

内部使用清晰枚举，中文仅作展示映射，避免旧版「待审核/待处理/待补正」语义混杂。

| 对象 | 关键字段 | 状态流 |
|---|---|---|
| 主体 `merchants` | 许可证、负责人、风险等级、绑定状态、设备 | 已绑定 / 未关联设备 |
| 设备 `devices` | 所属主体、健康度、心跳 | 在线 / 离线 / 待关联 |
| 风险 `alerts` | 类型、等级、置信度、证据、来源 | 待复核 → 已采纳（生成工单）/ 已忽略 |
| 工单 `workOrders` | 来源、要求、证据、整改内容、时间线 | 待整改 → 整改待审核 → 已办结 / 驳回待补正；或 → 申诉审核中 |
| 审批 `approvals` | 类型、对象、状态、结论 | 待镇级审核 → 已通过 / 已驳回 |

### 工单状态机

```
待整改 ──提交整改──▶ 整改待审核 ──通过──▶ 已办结
   │                    │
   │                    └──驳回──▶ 驳回待补正 ──补正──▶ 整改待审核
   │
   └──发起申诉──▶ 申诉审核中 ──通过──▶ 已办结（申诉通过）
                          └──驳回──▶ 待整改（继续整改）
```

### 审批类型与联动效果

| 审批类型 | 通过后 | 驳回后 |
|---|---|---|
| 整改审核 | 工单「已办结」 | 工单「驳回待补正」+ 记录驳回原因 |
| 申诉审核 | 工单「已办结」（申诉通过） | 工单回到「待整改」 |
| 主体变更 | 写入正式主体档案 | 申请驳回，正式档案不变 |
| 绑定审核 | 设备关联主体并置在线 | 维持未关联 |
| 解绑审核 | 移除设备关联 | 维持绑定 |

## 角色权限

| 角色 | 数据范围 | 关键权限 |
|---|---|---|
| 区级（R01） | 全区 | 查看全区、督办、查看审批详情，不直接审核 |
| 镇级（R02） | 本镇（演示默认东桥镇） | 复核风险、审核审批、设备关联 |
| 商户 | 当前绑定主体 | 提交整改/申诉/补正、主体变更、解绑申请 |

## 核心演示脚本

> 建议先打开 `index.html`，点击「重置演示数据」，然后两页并排打开（管理端 + 商户端）。

### 场景 A：AI 告警派单（推荐）
1. 管理端「风险中心」找到 `AI-20260810-001`（后厨未戴口罩，待复核）。
2. 点击「采纳派单」→ 生成工单 `WO-xxxx`，告警变为「已采纳」。
3. 切换到商户端首页，出现「后厨从业人员未佩戴口罩」待办。

### 场景 B：整改与审核
1. 商户端进入该工单 → 「提交整改」，填写说明与照片。
2. 管理端「审批中心」出现「整改审核」待办。
3. 镇级角色点「审核通过」→ 商户端该工单变为「已办结」。

### 场景 C：驳回与补正
1. 场景 B 中改为「驳回」，填写原因。
2. 商户端工单变为「待补正」并显示驳回原因。
3. 商户补正提交 → 管理端再次出现待审核。

### 场景 D：申诉分支
1. 商户端对「待整改」工单「发起申诉」。
2. 管理端审批中心出现「申诉审核」。
3. 通过 → 工单关闭；驳回 → 回到整改。

### 场景 E：主体变更 / 解绑 / 设备关联
1. 商户端「主体」→「变更」提交变更申请。
2. 管理端「审批中心」通过后，主体正式档案更新。
3. 管理端「设备治理」对 `D-CAM-201`（待关联）提交绑定申请。

## 关键校验点

- **两端一致**：同一工单/审批编号在两端状态、时间线一致。
- **状态流转可追溯**：工单详情时间线记录每一跳。
- **驳回必填**：管理端驳回、忽略风险不填原因会阻止。
- **角色约束**：区级角色审批详情显示「仅督办」，需切镇级执行。
- **数据可重置**：任一端或导航页「重置演示数据」均可恢复初始状态。

## 运行方式

直接双击/浏览器打开任一 HTML 即可，无需构建。依赖 Lucide 图标 CDN；离线时图标缺失不影响核心数据流转。
